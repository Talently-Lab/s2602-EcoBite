# AGENTS.md

## Monorepo (pnpm only)
- `pnpm-workspace.yaml` packages: `frontend`, `backend`, `api-portal`. Single root `pnpm-lock.yaml`, `packageManager: pnpm@10.34.5`, Node 22+.
- Root scripts (from repo root): `pnpm dev:frontend` / `pnpm dev:backend` / `pnpm dev:portal` (`--filter`), `pnpm build` (`pnpm -r build`), `pnpm build:portal` (portal only), `pnpm lint` (frontend only — `pnpm -r lint` for all packages). Or `cd frontend|backend|api-portal` and run package scripts directly. Never `npm`/`yarn`.
- `pnpm-workspace.yaml` pins security overrides (`mysql2`, `deepmerge-ts`, `source-map-js`) plus `auditConfig` ignores — don't change without checking the CI audit step.
- Commits follow `.github/git-commit-instructions.md`: Conventional Commits in English, mandatory scope, blank line between title and body.

## CI (backend + portal only)
- Workflows `.github/workflows/backend-ci.yml` / `api-portal-ci.yml`: push to `main`, PRs, manual dispatch. No path filters.
- Backend order matters: `audit` (moderate, blocking) → `lint` → `build` (generates the Prisma client) → `typecheck` → `check:api`. CI uses a placeholder `DATABASE_URL` — no real DB or secrets.
- Neither workflow touches `frontend/`; don't assume frontend coverage. Local lint flow: `docs/code-quality.md`.

## Backend (`backend/`, Express 5 + TS)
- `pnpm dev` = `tsx watch src/index.ts` · `pnpm build` = `prisma generate && tsc` (out `dist/`, `rootDir: src`, `module/nodeResolution: NodeNext`) · `pnpm start` = `node dist/index.js` · `pnpm lint` (oxlint) · `pnpm typecheck` (`tsc --noEmit` + import tsconfig) · `pnpm check:api` (Node runner + tsx over `tests/api.test.ts` and `tests/import-analyst-data.test.ts`, Prisma double, no real PostgreSQL) · `pnpm prisma:migrate|generate|deploy|seed|studio` · `pnpm data:import` (defaults to `--dry-run`; `--apply` only against an isolated DB) · `pnpm check:deployed`.
- Env: copy `backend/.env.example` → `backend/.env` (`PORT`, `DATABASE_URL`, optional `DIRECT_URL`/`TRUST_PROXY_HOPS`, required `JWT_SECRET`, optional `CORS_ORIGINS`; Doppler is the alternative to `.env`). Loaded via `import 'dotenv/config'` in `src/index.ts` — keep that import first. Never read real secrets to perform development checks.
- Entrypoint `src/index.ts` validates config and runs `SELECT 1` via Prisma before `listen`. `src/app.ts` creates the Express app; routes → controllers → services, with auth/error middleware. `/api/restaurants`, `/api/users/register`, `/api/users/login`, and protected `/api/users/me` are implemented; see `backend/README.md` for contracts and deployment limits.
- The stub is `GET /api` only; unknown routes return JSON 404. Do not reintroduce a catch-all `apiRouter.use('/')`.
- `backend/openapi.yaml` is the canonical contract (consumed by the portal and frontend, served at `/api/openapi.yaml`, rendered by Scalar at `/docs`) — update it on any contract change. Errors are `{"error":"msg"}`; POST body limit 16 KiB; auth routes share 20 attempts/IP/15min.
- DB: PostgreSQL 16 via `backend/docker-compose.yml` (`docker compose up -d`, named volume `ecobite-pgdata`). Prisma 7: connection URL lives in `prisma.config.ts` (not the schema), client uses `@prisma/adapter-pg` and is generated to `src/generated/prisma` (gitignored) — always import the singleton from `src/lib/prisma.ts`. Prisma 7 `migrate dev` does **not** run `generate` or the seed; run them explicitly.
- Source of truth: `prisma/schema.prisma` (mirrored in `docs/database/DER.md`, updated for Rebeca's S3 handoff dated 15/10/2026). camelCase models mapped to Spanish snake_case tables/columns via `@map`/`@@map`. Enums: `rol` `CLIENTE|ADMIN_PLATAFORMA|RESTAURANTE_ADMIN` (public registration stays `CLIENTE`; no new admin permissions or restaurant login), `tipo_transporte` `BICICLETA|VEHICULO_ELECTRICO`, `pedido_estado` `PENDIENTE|COMPLETADO|CANCELADO|EN_PREPARACION`. `producto_empaque.envases_por_unidad >= 1` is a raw SQL CHECK in the init migration (Prisma can't declare it) — keep it when editing migrations. Never return `password_hash` from the API.
- Seed (`prisma/seed.ts`, idempotent upserts): 48 CABA `zona` rows + 8 `empaques`. Restaurants/products come later from the Data Analyst — don't invent them. The analyst dataset goes through `data:import`; never `--apply` against Neon without approval.

## Frontend (`frontend/`, Vite 8 + React 19 + Tailwind 4)
- `pnpm dev|build|lint|preview`; `build` = `tsc -b && vite build` (project references `tsconfig.json` → `tsconfig.app.json` + `tsconfig.node.json`, typecheck runs first).
- Entrypoint `src/main.tsx` → `src/router.tsx` (`createBrowserRouter`, all pages `lazy()`, `/` → `/home`). Pages: `Dashboard`, `Catalog`, `DetailProduct`, `Auth` (`/auth`, hosts `LoginForm`/`RegisterForm`), `Orders`, `MyImpact`, `Home`, `NotFound`. Shared chrome lives in `src/pages/layout/MainLayout.tsx` (Navbar + max-w-7xl main) — wrap pages with it instead of mounting `Navbar` directly.
- Data layer: `src/services/*.service.ts` (plain async fetch fns) consumed via TanStack Query in `src/hooks/use*.ts`. Services throw errors instead of returning them, so mutations reach error state. `QueryClient` (staleTime 1min, `refetchOnWindowFocus: false`, `retry: 1`) + `<Suspense fallback={<PageSkeleton/>}>` are wired in `main.tsx`; devtools are `lazy()` + `import.meta.env.DEV`-gated so they never ship to prod. New hooks must work with `placeholderData`/fallbacks, not `useState`+`useEffect` fetching.
- Auth forms use RHF + `zodResolver` with schemas in `src/schemas/` (`registerSchema = loginSchema.extend({...})`, zod v4); mutations live in `src/hooks/useAuth.ts` (`useLogin`/`useRegister`). Real payloads: login `{email, password}` (never `name`); register `{name, email, password}` — the backend rejects unknown fields (400), so strip `confirmPassword` before mutating. Server errors go to a red banner atop the form via `setError("root.server")` (cleared with `clearErrors` on each submit); field errors render below their input with `aria-invalid` (red border is automatic).
- `PasswordField` accepts an RHF `register` spread plus an `error` prop; its eye toggle matches its aria-label, turns `text-destructive` on error, and native `::-ms-reveal` is hidden in `src/index.css` so only the custom toggle shows.
- Env: copy `frontend/.env.example` → `frontend/.env` (`VITE_API_URL`, no default). Gotcha: `restaurants.service.ts` reads `import.meta.env.VITE_API_URL` with **no fallback** and silently returns `MOCK_RESTAURANTS` (`src/lib/mocks.ts`) on any fetch failure — if Catalog shows mocks, check the env/backend first. Types live in `src/types/` (e.g. `restaurant.ts`).
- Alias `@/*` → `./src/*` must stay in sync in `vite.config.ts` (`path.resolve(__dirname, "./src")`), `tsconfig.app.json`, and root `tsconfig.json` (`files: []`, `baseUrl: "."`, `ignoreDeprecations: "6.0"`) or shadcn/build breaks.
- Tailwind 4 via `@tailwindcss/vite`, no config file. Tokens live in `src/index.css` (`@theme inline`); keep `@import` order: `tailwindcss`, `tw-animate-css`, `shadcn/tailwind.css`, `@fontsource-variable/inter`.
- Dark mode is dual: `dark:` utilities are **class-based** (`@custom-variant dark (&:is(.dark *))`) while tokens switch via **both** `@media (prefers-color-scheme: dark)` and `.dark`. The `.dark` class is synced from the OS by the inline script in `index.html` + the `matchMedia` listener in `main.tsx` — keep both, or `dark:*` utilities silently stop working. Light mode is source of truth for contrast; verify dark ratios (AA 4.5:1) after token changes.
- shadcn (`components.json`): style `base-vega`, `rsc: false`, css `src/index.css`, `baseColor: neutral`, `cssVariables: true`, icon `lucide`. `cn()` is a re-export from the `cn` package in `src/lib/utils.ts` — import via `@/lib/utils`, UI via `@/components/ui/<name>`. Add components with `pnpm dlx shadcn@latest add <name>` from `frontend/`.
- Lint is `oxlint` (`.oxlintrc.json`, react+typescript plugins, `rules-of-hooks: error`), not ESLint. No test runner and no frontend CI job — don't invent either.

## API portal (`api-portal/`, Next.js App Router + React + Tailwind 4)
- Backend-owned workspace, separate from the customer `frontend/`. Root `pnpm dev:portal` uses port 3001 with hot reload; `pnpm build:portal` builds only the portal. After building, `pnpm --filter api-portal start` serves the production build on port 3001.
- `app/layout.tsx` owns the shared sidebar and main landmark. Overview is a viewport-height, five-column template. `app/components/OverviewColumn.tsx` provides four blocks per column: empty outer spacers and two middle content slots, with alternating top offsets. Preserve that composition and avoid page scrolling. `/docs` redirects to the backend's Scalar reference (`API_DOCS_URL`, see `api-portal/.env.example`). `/status` and `/changelog` are blank pages awaiting user-led design; do not invent page content or telemetry.
- Tailwind 4 tokens and locally packaged Plus Jakarta Sans / Roboto Mono fonts live in `app/globals.css`; no browser CDN or traditional Tailwind config. Use dark green for text on light backgrounds; bright brand greens are accents, not small text.
- No auth, API calls, Scalar, or monitoring is implemented yet. The account panel is explicitly a preview and logout is disabled. Portal Google OAuth must remain separate from customer API JWT authentication.
- `app/components/PortalIcons.tsx` contains temporary prototype icons, not Nucleo exports. Replace only with authorized assets; do not install account/editor integrations or claim licensed assets are available without confirmation.
- Verification: `pnpm --filter api-portal lint`, `pnpm --filter api-portal typecheck` (`next typegen && tsc --noEmit`), and `pnpm --filter api-portal build`. No test runner. Builds require no API, database, or OAuth credentials.
